面向中文用户的 **Work 专家团队 × ZCode 专家团队 × Work 单兵职业 × ZCode 单兵工程 × 273 插件图鉴**。

### <https://zhangsugang.github.io/zcode-plugin-guide/>

单文件离线页面，无远程脚本和字体，也可下载后双击使用。

## 四种运行模式（各 100 个，共 400 个可下载工作区）

### Work 专家团队（100 个）

- 热门 60 · 稳定 25 · 蓝海 15，可按梯队筛选。
- 每个团队 5 个岗位、1 个主专家（lead），角色从 200 个可复用岗位注册表按需最小编队。
- 根 `AGENTS.md` 由 ZCode 自动加载，作为主路由。
- `.zcode/team.json` 提供机器可读的岗位、触发条件、依赖和并行组。
- `.zcode/commands/start-team.md` 提供 `/start-team` 启动入口。
- `.zcode/skills/team-router/SKILL.md` 提供可发现的团队路由技能。
- 实际子任务通过 ZCode Agent 工具的 `general-purpose` 子智能体执行；独立岗位并行、依赖岗位串行。
- Agent 工具不可用时明确进入主会话串行降级模式，不虚构已路由。

### ZCode 专家团队（100 个）

- 热门 60 · 稳定 25 · 蓝海 15。
- 每个项目 5 个工程岗位，覆盖架构规格、核心实现、测试质量、安全隐私、发布运行。
- 具备与 Work 团队相同的有效路由入口、依赖规则、统一交接协议和团队 ZIP。

### Work 单兵职业（100 个）

- 民事/刑事律师、中医/外科/儿科医生等细分职业，大部分一人身兼多职场景也适用。
- 每个工作区只有一个专业主体，不生成研究员、分析师、复核员等子专家。
- 澄清、取证、分析、制作和复核由同一专家按阶段完成。

### ZCode 单兵工程（100 个）

- React、Java Spring、RAG、Kubernetes、授权渗透测试等细到技术栈的工程工种。
- 每个工作区只有一个工程主体。
- 规格、架构、实现、测试、安全和发布由同一专家按阶段门禁完成。

## 启动 prompt

每个团队包和单兵包都包含根级 `START-PROMPT.md`。网页详情可以直接预览和复制。

启动 prompt 会要求 ZCode：

1. 检查工作区文件和 JSON。
2. 读取 `AGENTS.md`、流程和 Markdown 记忆。
3. 只从明确模板创建安全的本地配置，不覆盖已有文件。
4. 验证插件、Skill、Command、MCP 或工具的真实状态。
5. 把推荐插件清单与实际安装状态分开。
6. 返回 `READY / PARTIAL / BLOCKED` 启动报告。

## 下载包真实性

- ZIP 在浏览器中点击时即时生成：共享模板 + 目录数据现场构建，页面不内嵌 400 个工作区负载。
- `.zcode/recommended-plugins.json` 是推荐清单，不代表插件已安装。
- Markdown 文件是默认工作区记忆。
- SQLite 文件只是可选 schema，未执行前不代表数据库已经运行。
- ZIP 不包含真实密钥、Cookie、`.env`、登录状态、个人数据或本地数据库。

## 273 个插件中文图鉴

每个插件提供：

- 中文名称。
- 准确英文安装名。
- 功能与适用场景。
- 推荐星级和使用门槛。
- 使用方法和注意事项。

## 使用方法

1. 打开在线页面。
2. 从导航选择：Work 专家团队 / ZCode 专家团队 / Work 单兵职业 / ZCode 单兵工程 / 插件功能说明。
3. 打开团队或单兵详情。
4. 复制启动 prompt。
5. 下载对应 ZIP，用 ZCode 打开解压目录（一个文件夹就是一个完整项目）。
6. 把启动 prompt 发送给 ZCode，等待启动报告后再提交任务。
